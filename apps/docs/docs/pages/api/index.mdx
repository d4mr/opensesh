# API overview

opensesh exposes a REST API for reading and managing program data programmatically — 64 operations covering the whole platform, grouped by tag: **Organization, Events, Submissions, Speakers, CRM, Pipeline, Reviews, Agenda, Widgets, Integrations, Mail**. Every operation is documented in the sidebar, and the same surface is described by the machine-readable [OpenAPI document](#openapi-spec) — ideal for wiring up an MCP server or generating a typed client.

## Base URL

```
https://app.opensesh.io/api/v1
```

If you self-host, replace the host with your own deployment's domain.

## Authentication

Every request is authenticated with an organization API key sent as a bearer token:

```bash
curl https://app.opensesh.io/api/v1/... \
  -H "Authorization: Bearer osk_..."
```

API keys are managed in **Organization settings → API keys**. Keys are scoped to an organization, start with the `osk_` prefix, and are shown once at creation — store them in a secret manager. Revoke a key from the same page at any time; revocation takes effect immediately.

## OpenAPI spec

The API is described by an OpenAPI 3.1 document, served by the API itself:

```
GET https://app.opensesh.io/api/v1/openapi.json
```

Use it to generate clients or import the API into your tooling.

## Conventions

- Requests and responses are JSON (`Content-Type: application/json`).
- Resources are scoped to the organization the API key belongs to.
- Missing or invalid keys return `401 Unauthorized`; keys without access to a resource return `404 Not Found`.

## Endpoint reference

The per-tag pages in the sidebar are generated straight from the OpenAPI document, so they always match what the server actually validates: [Organization](/api/organization), [Events](/api/events), [Submissions](/api/submissions), [Speakers](/api/speakers), [Reviews](/api/reviews), [Agenda](/api/agenda), [CRM](/api/crm), [Pipeline](/api/pipeline), [Widgets](/api/widgets), [Mail](/api/mail), and [Integrations](/api/integrations).
